# Диалог — локальный помощник менеджера

Небольшой сервис для тестового задания: менеджер вставляет обращение клиента и контекст переписки, а сервис возвращает **ответ клиенту** и отдельную **подсказку по допродаже**. Ответ можно отредактировать и скопировать. Отправку клиенту выполняет менеджер.

Генерация работает через локальную `qwen3.5:9b-q4_K_M` в Ollama. Поиск использует локальную `bge-m3` и сохраненный на диске индекс Chroma. Даже небольшая демонстрационная база обрабатывается через поиск: в Qwen передаются только выбранные фрагменты с ограничением объема.

## Быстрый запуск в Windows

Потребуются Python 3.11, [Ollama](https://ollama.com/download) и свободное место для двух моделей. Команды ниже выполняются в PowerShell из корня проекта. Активация виртуального окружения не обязательна: команды явно используют его Python.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
ollama pull qwen3.5:9b-q4_K_M
ollama pull bge-m3
```

`requirements-dev.txt` включает зависимости приложения и pytest. Для запуска без тестов достаточно `requirements.txt`. Проверенные версии всех пакетов сохранены в `requirements.lock.txt`; для воспроизводимой установки используйте `pip install -r requirements.lock.txt`.

Ollama должна быть запущена. Если установленное приложение Ollama еще не запустило сервер, выполните `ollama serve` в отдельном окне терминала. Проверить загруженные модели можно командой `ollama list`.

Настройки по умолчанию подходят для локального демо. При необходимости создайте `.env` из шаблона и измените нужные параметры:

```powershell
Copy-Item .env.example .env
```

Создайте индекс, затем запустите приложение:

```powershell
.\.venv\Scripts\python.exe -m app.index
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте **[http://127.0.0.1:8000](http://127.0.0.1:8000)**. Вместо команды uvicorn можно использовать готовый скрипт:

```powershell
.\start.ps1
```

Он запускает сервер из `.venv` на `127.0.0.1:8000`. Другой порт: `./start.ps1 -Port 8001`. Остановка сервера — `Ctrl+C` в его терминале.

Интернет нужен для первоначальной установки зависимостей и загрузки моделей. После подготовки локальный интерфейс, поиск и генерация работают без обращения к облачной модели.

## Как пользоваться

1. Выберите демонстрационный пример либо вставьте новое сообщение клиента.
2. При необходимости добавьте историю с авторами реплик:

   ```text
   Клиент: Выбираю кофемашину для черного кофе.
   Менеджер: Подойдет Linea Black. Добавить пачку Daily Blend?
   Клиент: Спасибо, кофе у меня уже есть.
   ```

3. Нажмите «Подготовить ответ» или `Ctrl+Enter`.
4. Проверьте и при необходимости отредактируйте клиентский ответ. Кнопка «Скопировать» копирует только этот блок; внутренняя подсказка остается отдельно.

Под блоками результата доступны найденные источники и время обработки. Если изменить обращение или историю, предыдущий ответ помечается как устаревший. Ошибка сервиса сохраняет введенный текст.

Демо использует вымышленный магазин «Кофе рядом». Товары, цены, условия доставки и обслуживания в базе созданы для проверки приложения и не являются политиками реального бизнеса.

## Что происходит внутри

```text
knowledge.json → отдельная индексация → bge-m3 → Chroma на диске
                                                    ↑
обращение + история → FastAPI → поиск фактов и допродаж
                                      ↓
                          ограниченный набор фрагментов
                                      ↓
                         qwen3.5:9b-q4_K_M в Ollama
                                      ↓
                       ответ клиенту + подсказка менеджеру
```

- **Индексация** читает JSON, объединяет короткие абзацы в фрагменты и вычисляет их векторы. Хеш содержимого позволяет повторно обрабатывать только измененные записи; удаленные записи и лишние фрагменты удаляются из индекса. Изменение модели поиска или настроек разбиения требует переиндексации.
- **Обработка обращения** использует готовую коллекцию Chroma. Файл базы знаний при каждом запросе целиком не читается: для проверки актуальности используются метаданные индекса и характеристики файла.
- **Поиск** сначала выбирает подходящие товары и FAQ по смыслу. Затем ищет связанные допродажи по `product_id`, оставляет результаты выше порога сходства и укладывает их в бюджет контекста. Предложение включается вместе с фактом о соответствующем товаре. При признаках жалобы, возврата или неисправности действует простая языковая эвристика: поиск по теме проблемы среди FAQ, до двух фрагментов, без допродаж. Она уменьшает влияние названия товара на поиск условий поддержки.
- **Генерация** получает найденные фрагменты, последнее обращение и историю. Инструкции требуют опираться на найденные сведения, учитывать прежние предложения и отказы, не предлагать допродажу при жалобе. Формат ответа ограничен JSON-схемой и проверяется сервером.
- **Недостаток данных** обрабатывается отдельно от ошибки индекса. При пустой выдаче возвращается безопасный запрос уточнения без генерации неподтвержденных коммерческих условий. Если среди источников нет допродаж, сервер убирает предложение даже при его появлении в ответе модели.
- **Защита от неуместной допродажи** работает дополнительно к инструкциям модели: при распознанной жалобе или отказе предложения исключаются из контекста, модель получает запрет допродажи, а подсказка менеджеру заменяется фиксированным объяснением. Краткое «нет» и фраза о наличии товара считаются отказом только в контексте предшествующего предложения менеджера. Ответ «нет» на вопрос «У вас уже есть зерна?» сам по себе допродажу не блокирует.

Эти правила — консервативная языковая эвристика, преимущественно для русского языка. Распознанный отказ блокирует все допродажи в переданном диалоге, даже если касался одного товара или клиент позднее передумал. Правила не заменяют проверку ответа менеджером; учитывается только переданная переписка, постоянной памяти о клиенте нет.

Для ограничения контекста используется консервативная оценка: **один байт UTF-8 считается одной единицей бюджета**. Это верхняя оценка, а не точный подсчет токенизатором Qwen. В бюджет найденных фрагментов входят также их метаданные. Общий запрос проверяется отдельно, с резервом для ответа модели и служебного оформления.

История не обрезается молча: если весь выбранный контекст не помещается, сервер просит сократить переписку, сохранив предложения менеджера и отказы клиента. Поэтому максимально допустимые размеры полей API не гарантируют, что любая комбинация этих размеров поместится в контекст модели.

## База знаний и примеры

Исходная база находится в [data/knowledge.json](data/knowledge.json), демонстрационные диалоги — в [data/examples.json](data/examples.json). В стартовой базе 16 записей; предусмотрено 6 примеров: цена, доставка, вопрос вне базы, уход, отказ от предложения и жалоба.

Формат записи:

```json
{
  "id": "luna-beans-offer",
  "title": "Дополнение к Luna Milk: кофе для первых напитков",
  "kind": "upsell",
  "product_id": "luna-milk",
  "updated_at": "2026-10-01",
  "text": "К Luna Milk можно предложить Daily Blend 250 г за 650 ₽, если у клиента нет зерен. Не предлагать после отказа или если предложение уже звучало."
}
```

`id` должен быть уникальным. `kind` принимает `product`, `faq` или `upsell`. Для товара и допродажи требуется `product_id`; допродажа должна ссылаться на существующий товар. У FAQ без привязки к товару можно указать `null`. Поле `text` содержит факты, условия применения и ограничения предложения.

Абзацы, разделенные пустой строкой (`\n\n`), считаются смысловыми блоками. Цену и условия ее применения храните в одном абзаце. Такой абзац не разрезается посередине; если он вместе с метаданными превышает жесткий бюджет контекста, индексация сообщает об ошибке. Длинный текст необходимо разделить на самостоятельные абзацы либо увеличить бюджет и размер контекста модели согласованно.

После изменения базы повторите:

```powershell
.\.venv\Scripts\python.exe -m app.index
```

До переиндексации измененная база помечается как неготовая. Незавершенная индексация также не используется для ответов. Сам индекс хранится в `data/chroma/` и сохраняется между запусками.

У каждого примера в `examples.json` есть `id`, `title`, `message`, массив `history`, а также `expected_sources` и `expected_behavior` для проверки. Авторы реплик в JSON — `client` и `manager`.

## Настройки

Все параметры доступны в [.env.example](.env.example). Основные значения:

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `OLLAMA_BASE_URL` | `http://localhost:11434` | Адрес локальной Ollama |
| `OLLAMA_MODEL` | `qwen3.5:9b-q4_K_M` | Закрепленная модель генерации |
| `EMBEDDING_MODEL` | `bge-m3` | Закрепленная модель поиска |
| `OLLAMA_TIMEOUT` | `180` | Ожидание ответа Ollama, секунды |
| `OLLAMA_NUM_CTX` | `8192` | Контекст модели |
| `OLLAMA_NUM_PREDICT` | `700` | Максимальная длина генерации в токенах |
| `TOP_K` / `UPSELL_TOP_K` | `5` / `2` | Число кандидатов фактов и допродаж |
| `SIMILARITY_THRESHOLD` | `0.45` | Минимальная близость найденного фрагмента |
| `CONTEXT_TOKEN_BUDGET` | `3000` | Жесткий бюджет найденных фрагментов, оценка по UTF-8 байтам |
| `CHUNK_TOKEN_BUDGET` | `400` | Целевой размер объединения абзацев, та же оценка |
| `SERVICE_API_KEY` | пусто | Ключ доступа для внешнего подключения |

Бюджет фрагментов и контекст модели ограничиваются независимо от размера базы. Увеличение `OLLAMA_NUM_CTX` увеличивает потребление памяти. Порог сходства следует оценивать на примерах своей предметной области: он не является вероятностью правильности ответа.

## HTTP API

Документация FastAPI доступна на [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/health` | Готовность моделей и индекса, доступен без ключа |
| `GET` | `/examples` | Демонстрационные диалоги |
| `POST` | `/suggest` | Ответ клиенту и внутренняя подсказка |

Пример запроса к `/suggest`:

```json
{
  "message": "Тогда беру Linea Black. Напомните цену кофемашины.",
  "history": [
    {"role": "manager", "content": "Добавить Daily Blend 250 г за 650 ₽?"},
    {"role": "client", "content": "Нет, кофе у меня уже есть."}
  ]
}
```

Ограничения: новое сообщение до 6000 символов, история до 30 реплик, каждая до 6000 символов, суммарный текст истории до 20000 символов. Пустые сообщения и неизвестные роли отклоняются. Дополнительно проверяется вместимость контекста модели.

Форма успешного ответа ниже иллюстративная: формулировки, найденные источники, оценки и длительности зависят от запроса и оборудования.

```json
{
  "client_reply": "Linea Black стоит 27 900 ₽.",
  "manager_tip": "Сейчас допродажа неуместна: клиент уже отказался от кофе.",
  "sources": [
    {"id": "linea-black:1", "title": "Кофемашина Linea Black: черный кофе и цена", "kind": "product", "score": 0.72}
  ],
  "timings": {"retrieval_ms": 120, "generation_ms": 4500, "total_ms": 4620}
}
```

Ошибки имеют форму `{"error":{"code":"...","message":"..."}}`: например, `401` при отсутствии ключа, `422` при некорректном вводе или превышении контекста, `429` при уже выполняющейся генерации и `504` при тайм-ауте Ollama. Ошибки подготовки индекса и некорректный ответ модели также показываются понятным сообщением. Одновременно сервис готовит один ответ.

Если настроен `SERVICE_API_KEY`, передавайте его к `/suggest` и `/examples` в заголовке `Authorization: Bearer <ключ>`.

## Проверки

Изолированные проверки API, правил обработки ответа и работы индекса:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Они используют подмену Ollama и не требуют запуска Qwen. Покрываются ограничения ввода, структура результата, ошибки модели, отсутствие сведений, недопустимые допродажи, обновление/удаление записей, связанные предложения, бюджеты и готовность индекса.

Проверка поиска на настоящей `bge-m3` и подготовленной базе:

```powershell
.\.venv\Scripts\python.exe scripts/evaluate.py
```

Проверка тех же диалогов с генерацией Qwen:

```powershell
.\.venv\Scripts\python.exe scripts/evaluate.py --generate --output logs/evaluation.json
```

Отчет создается локально в `logs/evaluation.json` и не включен в репозиторий. Он содержит ожидаемые и найденные источники, размеры контекста, ответы и время выполнения. Скрипт сигнализирует об отсутствии ожидаемых источников и ошибках; смысловую корректность ответов нужно сопоставить с `expected_behavior`. Запуск `--generate` может занять несколько минут, особенно при первой загрузке модели.

Во время разработки зафиксирован успешный изолированный прогон: **64 проверки пройдены**. В проведенном тогда прогоне с настоящими моделями все **6 сценариев** получили `expected_found: true`: ожидаемые источники найдены, а вопрос вне базы дал пустую выдачу. В сценариях отказа и жалобы допродажа была заблокирована; для вопроса вне базы вернулось уточнение без вызова Qwen. Это результаты предыдущих запусков; для проверки своего окружения используйте команды выше.

Среда замеров: Windows, Python 3.11, **32 ГБ оперативной памяти, NVIDIA GeForce RTX 3060 с 12 ГБ видеопамяти**. В этом прогоне первая генерация с загрузкой модели заняла **10,3 с**, последующие — **2,3–4,6 с**; полная обработка последующих запросов с генерацией — **2,3–4,7 с**. Ответ при отсутствии источников занял около **0,09 с**, без генерации. Первый отдельный поиск с загрузкой модели эмбеддингов занял около **3,3 с**.

Это измерения одного демонстрационного прогона на указанном компьютере, а не минимальные требования или обещание постоянной скорости. Время зависит от загрузки моделей, объема контекста, длины ответа и доступной памяти. Проверка ожидаемых источников не доказывает правильность каждой формулировки: ответы остаются черновиками для менеджера.

## Локальная обработка и доступ

В приложении нет облачного API генерации. Настройки принимают для Ollama только `localhost` или IP локальной сети; переадресации HTTP отключены. У Chroma отключена анонимная телеметрия и стандартная модель эмбеддингов: векторы рассчитывает выбранная локальная `bge-m3`.

Интерфейс не сохраняет диалоги в браузерное хранилище, а сервер приложения не пишет сообщения клиентов и ответы модели в журнал. В журнал попадают идентификаторы найденных источников и время обработки. Явно запущенная проверка `scripts/evaluate.py --generate` сохраняет ответы демонстрационных сценариев в свой JSON-отчет.

При локальном запуске ключ можно оставить пустым; сервер привязан к `127.0.0.1`, а без ключа допускает только локальные значения заголовка Host. Для доступа через публичный HTTPS-туннель **обязательно задайте `SERVICE_API_KEY`** и перезапустите сервер. Интерфейс содержит поле «Ключ доступа» внутри раскрывающегося блока состояния; ключ хранится только до перезагрузки страницы и не передается в URL. Это один общий ключ сервиса; отдельных учетных записей менеджеров в тестовом нет. Порт Ollama для интеграции публиковать не требуется.

Внешний доступ нужен лишь для опционального встроенного виджета amoCRM. Для выбранного режима отдельной вкладки на том же компьютере он не требуется. Скрипт `scripts/start-tunnel.ps1` запускается отдельно и требует настроенного ключа.

## Подключение amoCRM

**Выбранный режим MVP — помощник в отдельной вкладке рядом с amoCRM.** Откройте сделку в своем аккаунте и локальный помощник в соседней вкладке. Для демонстрации можно использовать вымышленный диалог из `data/examples.json`; учетные данные и сделки конкретного аккаунта для запуска сервиса не требуются.

В репозитории есть [исходники опционального приватного виджета](integrations/amocrm/widget/) и скрипт его сборки. Установка виджета не входит в выбранный MVP; работа встроенного варианта внутри amoCRM не проверена.

Опциональный порядок сборки и установки описан в [docs/AMOCRM.md](docs/AMOCRM.md). Архив `widget.zip` создается локально и не включен в репозиторий. При сборке укажите свой контакт поддержки.

В первой версии переписка переносится вручную, поэтому менеджер должен включить в нее существенные предложения и отказы: пропущенные реплики помощнику неизвестны. Готовый ответ также вручную копируется в диалог amoCRM; внутренняя подсказка в копирование не включается. Автоматическое чтение истории конкретного мессенджера и отправка сообщений требуют отдельной проверки возможностей его интеграции. Подготовленный виджет не изменяет сделку и не отправляет клиенту ответ автоматически.
