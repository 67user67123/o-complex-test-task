# Помощник рядом с amoCRM и заготовка виджета

**Для MVP выбран режим отдельной вкладки:** менеджер работает в amoCRM и открывает помощник по адресу [http://127.0.0.1:8000](http://127.0.0.1:8000) на том же компьютере. Обращение и нужные реплики переносятся вручную. Сервис выдает ответ клиенту и внутреннюю подсказку менеджеру; ответ проверяет и отправляет менеджер. Публичный HTTPS-туннель для этого режима не используется.

## Состав MVP

- Помощник работает в отдельной вкладке на компьютере менеджера. Для локального запуска сервиса аккаунт amoCRM не требуется.
- Для демонстрации рядом с CRM можно открыть тестовую сделку в своем аккаунте и использовать учебные диалоги из [data/examples.json](../data/examples.json).
- Установка приватной интеграции и виджета не входит в выбранный MVP.
- В репозитории сохранены [исходники опционального виджета](../integrations/amocrm/widget/) и [скрипт сборки](../integrations/amocrm/build_widget.py). Архив создается локально; готовый `widget.zip` не включен в репозиторий. Встроенное отображение в настоящем аккаунте не проверено.

## Работа в выбранном режиме

1. Запустить Ollama и локальный FastAPI по инструкции в [README.md](../README.md); дождаться готовности моделей и базы знаний.
2. Открыть нужную сделку в своем аккаунте amoCRM и [локальный помощник](http://127.0.0.1:8000) в соседней вкладке.
3. Вручную перенести обращение клиента и нужную часть диалога в соответствующие поля помощника. Для демонстрации также доступны готовые примеры в интерфейсе.
4. Нажать «Подготовить ответ». Проверить два отдельных блока и при необходимости отредактировать клиентский ответ.
5. Скопировать только ответ клиенту в нужный диалог amoCRM. Решение об отправке принимает менеджер; подсказка по допродаже остается внутренней.

Локальный сервер привязан к `127.0.0.1:8000`; в этом режиме `SERVICE_API_KEY` можно оставить пустым. Встраивание, OAuth amoCRM и туннель для выполнения этих шагов не требуются.

## Опциональный виджет

Исходники виджета предусматривают размещение в правой колонке карточки сделки. «Открыть в карточке» раскрывает интерфейс в iframe; «Открыть отдельно» запускает его в новой вкладке. Для использования этих возможностей нужно собрать архив и установить интеграцию в своем аккаунте.

Перед установкой владелец аккаунта должен проверить доступность приватных интеграций и применимые условия amoCRM. См. [официальную инструкцию по созданию интеграции](https://www.amocrm.ru/developers/content/oauth/step-by-step) и [описание типов аккаунтов](https://www.amocrm.ru/developers/content/integrations/intro).

### Что потребуется для установки

- Активный аккаунт amoCRM и права администратора для создания и установки приватной интеграции.
- Запущенный сервис из этого проекта с подготовленной базой знаний и локальными моделями Ollama.
- HTTPS-адрес интерфейса сервиса, доступный браузеру менеджера, с доверенным сертификатом. Например, `https://assistant.example.com/` — это пример, его необходимо заменить своим адресом.
- При доступе к сервису вне локальной машины — настроенный ключ доступа сервиса. Менеджер вводит его в форму помощника; ключ не записывается в настройки виджета, URL или архив.
- Для встроенного окна сервер и промежуточный прокси должны разрешать встраивание для домена вашего аккаунта amoCRM. Иначе используйте открытие в новой вкладке. Заголовок `X-Frame-Options: DENY` или `SAMEORIGIN` на прокси может заблокировать iframe, даже если сервис разрешает встраивание.

Пример подходящей политики сервера: `Content-Security-Policy: frame-ancestors 'self' https://*.amocrm.ru https://*.amocrm.com`. Виджет обращается к странице приложения, поэтому браузер использует ее обычные запросы к FastAPI. Публиковать порт Ollama не требуется.

### Сборка архива

Из корня проекта:

```powershell
python integrations/amocrm/build_widget.py --support-email "support@example.com"
```

Замените демонстрационный адрес `support@example.com` на действующий контакт ответственного за приватную интеграцию. Команда создаст `integrations/amocrm/widget.zip`, заменив контакт только внутри локального архива. Исходный `manifest.json` останется шаблоном. Сборка без аргумента тоже доступна для локального просмотра, но оставляет явно помеченный технический адрес. Созданный архив не предназначен для добавления в репозиторий.

Сборщик использует стандартную библиотеку Python: читает JSON, проверяет UTF-8 без BOM и размеры логотипов, затем кладет файлы сразу в корень ZIP. Генератор логотипов и тура `generate_images.ps1` нужен только для изменения изображений; готовые PNG уже включены. Требования к структуре, локализациям, изображениям и туру описаны в [документации структуры виджета](https://www.amocrm.ru/developers/content/integrations/structure).

## Опциональное подключение в будущем

Следующие шаги не входят в выбранный режим MVP. Они применимы после решения вопроса с правом установки приватной интеграции; архив сам по себе не отменяет условия amoCRM.

### Временный HTTPS-адрес для локального демо

Задайте непустой `SERVICE_API_KEY` в `.env` и перезапустите FastAPI на `127.0.0.1:8000`. После готовности моделей и индекса запустите из корня проекта:

```powershell
.\scripts\start-tunnel.ps1
```

Скрипт проверяет `/health`, наличие ключа и то, что работающий сервер действительно требует этот ключ. Затем при необходимости скачивает переносимый `cloudflared.exe` из [официального релиза Cloudflare](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/downloads/) в `tools/` и запускает временный туннель только к `http://127.0.0.1:8000`. Ключ не выводится и не передается cloudflared.

Скопируйте напечатанный адрес `https://…trycloudflare.com` в настройку виджета. Процесс должен продолжать работать; `Ctrl+C` закрывает этот туннель, следующий запуск выдаст другой адрес. Quick Tunnel подходит для демонстрации и не требует аккаунта Cloudflare или своего домена. Условия описаны в [официальной инструкции Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/).

Системная служба не устанавливается, существующие процессы cloudflared не останавливаются. При обнаружении конфигурации в профиле `.cloudflared` скрипт завершится, не изменяя ее. Сам ключ менеджер вводит в форме помощника, в том числе при открытии из iframe.

### Загрузка виджета

1. Войти под администратором и открыть **амоМаркет → три точки рядом с «+ Webhooks» → «Создать интеграцию»**. При наличии права установки оформить приватную интеграцию для своего аккаунта, указать название и описание; локализации архива — `ru` и `en`. Условия создания интеграции принимает владелец аккаунта.
2. В редактировании интеграции загрузить `integrations/amocrm/widget.zip` в поле архива виджета и сохранить. Архив должен называться именно `widget.zip`; для новой интеграции `code` и `secret_key` в manifest не нужны. Порядок загрузки приведен в [инструкции amoCRM](https://www.amocrm.ru/developers/content/integrations/upload).
3. Открыть настройки виджета и указать полный HTTPS-адрес **интерфейса**, например `https://assistant.your-domain.ru/`. Не указывать `/suggest`, адрес Ollama, ключ доступа, параметры `?key=...` или фрагмент `#...`.
4. Сохранить/установить виджет. Поле адреса создается amoCRM из `settings` в manifest; используются стандартные callbacks `settings` и `onSave`, описанные в [WEB SDK](https://www.amocrm.ru/developers/content/web_sdk/settings).
5. Открыть существующую карточку сделки, раскрыть виджет «Помощник менеджера» в правой колонке и нажать «Открыть в карточке». Для более широкого окна воспользоваться «Открыть отдельно».
6. Если сервис требует ключ, ввести его в форму помощника. Вставить обращение и контекст переписки, получить результат, проверить и отредактировать ответ. Скопировать клиентский блок в диалог amoCRM вручную; подсказка менеджеру остается внутренней.

Размещение использует `locations: ["lcard-1", "settings"]` и `render_template()` — механизм [правой колонки карточки](https://www.amocrm.ru/developers/content/web_sdk/card). Сохранение адреса не проверяет доступность сервера; неверный формат адреса отображается ошибкой в виджете и не открывается. Доступность HTTPS проверяется фактической загрузкой страницы.

## Что проверить после установки

- Виджет виден в карточке сделки; настройки сохраняются после перезагрузки.
- Корректный HTTPS-адрес открывает сервис внутри карточки и в новой вкладке.
- HTTP-адрес, адрес с логином/паролем, query или fragment показывает понятную ошибку без открытия сервиса.
- При работе в iframe доступны ввод обращения, генерация и оба блока результата. В узкой колонке интерфейс прокручивается.
- Ключ вводится в интерфейсе сервиса и отсутствует в URL; после новой загрузки формы он запрашивается заново.
- Копирование ответа работает. Если браузер ограничивает Clipboard API внутри iframe, открыть помощник отдельно или выделить ответ и скопировать вручную.
- Виджет не отправляет сообщения и не изменяет сделку автоматически.

Это список приемки для аккаунта, а не отчет о выполненной живой проверке.

## Границы первой версии

Виджет не читает DOM переписки, не получает историю автоматически, не использует CRM OAuth-токены, не записывает примечания и не отправляет ответ клиенту. Он встраивает существующую форму сервиса. Текст диалога уходит в FastAPI только после действия менеджера в этой форме; в ссылках он не передается.

Доступ к истории стороннего WhatsApp/Telegram или другого канала следует проверять отдельно для конкретного установленного коннектора и его прав. Само наличие виджета не дает универсального доступа к чужому каналу. Собственная интеграция через API чатов требует регистрации канала и публичного endpoint для уведомлений; официальные условия приведены в [руководстве API чатов](https://www.amocrm.ru/developers/content/chats/chat-start). Этот этап не входит в подготовленный виджет.

Скрипты не создают аккаунты, каналы или DNS. Запуск HTTPS-туннеля предусмотрен отдельной опциональной командой; в выбранном MVP используется localhost. Публикация в общем каталоге amoCRM не выполняется.
